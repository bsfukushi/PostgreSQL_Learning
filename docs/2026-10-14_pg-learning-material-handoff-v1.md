# PostgreSQL学習資料（非エンジニア向け） 壁打ちハンドオフ v1

## 0. このドキュメントの目的

チームの非エンジニアメンバー向けに作る「PostgreSQL学習資料」の、目次・方針の壁打ちと体裁見本作成までの記録。次セッションで、決定事項を取りこぼさずに章の執筆へ進むための起点とする。

## 1. このセッションで何が起きたか

1. 「RDBの基礎、テーブル設計、JOIN、pgAdmin4の使い方」を学ぶ資料として目次の壁打ちを開始
2. ゴールが「自分でSQLを書く」から「**Claude Codeに正確に指示し、出てきたSQLと結果が意図通りか検証できる**（読む力・疑う力）」に転換
3. 前提条件（PoC環境、各自のPCにPostgreSQL 18、Windows、psql→MCP）、読者像（理屈を知りたい人、時間が取れない人）を順に確定
4. 目次を v0.1 → v0.6 まで改訂。v0.5 の時点で Claude Fable 5.1 に目次レビューを依頼し、「学ぶ順と手を動かせる順のズレ」など6点の重大指摘を反映
5. ボリューム削減のため、本冊2冊＋別冊の3冊構成（A案）を確定（v0.7）
6. 章ごとのMarkdownを正とするビルド方式で、体裁見本（第7章 JOINを読む／第10章 設計の5つの問い）を作成・公開。本文中のSQLは実DB（PostgreSQL 16）で実行し、結果表と照合済み

### 5.2 執筆前に裏取りが必要な事実
| 項目 | 確度 |
|---|---|
| COPY の `ON_ERROR ignore` は型変換エラーのみが対象（UNIQUE／NOT NULL違反はコマンド全体が失敗） | Fableは公式で確認と報告。Claudeは未再確認 |
| `REJECT_LIMIT`、`LOG_VERBOSITY silent` は v18 で追加 | Fableは公式で確認と報告 |
| PostgreSQL 18 で `EXPLAIN ANALYZE` に BUFFERS が自動で付く | リリースノートで確認済み |
| `RETURNING old/new`、`uuidv7()`、仮想生成列が既定、`initdb` でチェックサム既定有効、MD5パスワード非推奨 | リリースノートで確認済み |
| `NOT ENFORCED` は CHECK と外部キーのみ | リリースノートで確認済み |
| Windows：インストーラーが PostgreSQL の `bin` を PATH に追加しないことが多い | 中（要確認） |
| Windows：psqlの文字化け対策（`chcp 65001`、`\encoding UTF8`、Windows Terminal） | 中（各PCで再現確認） |
| Windows：`pgpass.conf` の場所（`%APPDATA%\postgresql\`） | 高（場所は要確認） |
| Claude Code が使うシェル（Git Bash／PowerShell）での `psql -c "..."` の引用符の扱い | 中（要確認） |
| Windowsのロケール名・照合順序の既定値、メンバー間で揃っているか | 低（第4章で全員に確認させる） |
| pg_bigm の Windows 向けバイナリの有無 | 低 |

## 8. 用語集（新規追加分）
- **読む力・疑う力**：この資料のゴール。SQLを自分で書く力より、Claude Codeが出したSQLと結果を読み、どこが怪しいかを判断する力を重視する
- **ズレの3分類**：エラーにならずに結果がズレる失敗の分類。「行が減る」（INNER JOINで相手なし、NULL）／「行が増える」（1対多のJOIN）／「値が変わる」（COUNT(*)、タイムゾーン、型変換、照合順序）。第6章で導入し、各章の失敗例にタグ付けする
- **検算の4手順**：①基準の表の件数 → ②処理後の件数 → ③差の理由を言葉で説明 → ④期待値と比較。③で説明できない結果は使わない
- **設計の5つの問い**：①1行は何を表すか（粒度）②何で同じものと判定するか ③1つに複数あるか ④あとで変わるか・履歴は要るか ⑤欠けるか・何で検索するか
- **本編と別冊の基準**：知らないと事故る／ズレに気づけない → 本編。知っていると上達する → 別冊
- **独自記法（章MD）**：`:::result N [wrong]`／`:::claude`／`:::quiz`／`:::why`／`:::check`／`[[用語]]`／`> 🔍`・`> 🧭`

## 9. 重要な設計原則
- **正は1か所**：章MDが正でHTMLは派生物。チェックリストは各章の1行が正で付録Cは集約。初期化SQLが正で pg_dump はスナップショット。同じ内容を2か所に持つと、資料自身が「AとBのズレ」を起こす
- **学ぶ順＝手を動かせる順**：概念を説明する章の時点で、道具とサンプルデータが揃っていること（Fableの最重要指摘）
- **安全網はClaude Codeより先**：Claude Codeを触らせる章（第5章）より前に、最低限の約束（禁止事項、接続ロール、確認方法）を教える
- **性能は断言せず、測らせる**：方式の良し悪しはデータ量と問い合わせで逆転する。計測の方法を教える
- **事実は裏取りしてから書く**：理屈派の読者には、誤った理由が致命的。v18の挙動は公式ドキュメントで確認し、確度を明記する
- **本文中のSQLは必ず実行して照合**：見本の段階から、SQLと結果表を実DBで突き合わせる仕組みを持つ
