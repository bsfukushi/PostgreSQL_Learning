## 決めたこと（2026-10-14、ともさん決定）
- 書く役（Opus、learner）と検証役（Sonnet、sql-checker サブエージェント、reviewer＝読むだけのロール）を分ける
- 検証役には「依頼文・SQL・結果の数字」だけを渡し、書く役の説明は渡さない（追認を防ぐ）
- 検証役には「正しい」と言わせず、別解との「一致・不一致」と「依頼とのずれ」だけを報告させる
- 判断は人。一致しても、基準の件数（a）と前提（e）を人が確かめる

## なぜ
- 同じモデルに「検証して」と頼むと、書いたときと同じ読み違いのまま「正しい」と答える（文法上は正しい SQL のズレに気づかない）
- 別モデルの効果が最も大きいのは「食い違ったときに止まれる」こと。一致は証明ではない
- 検証役が誤ってデータを変えると比較の意味がなくなるので、権限で「できない」状態にする

## 固定の抜け道（Claude Code 公式ドキュメントで確認）
- メインのモデルは .claude/settings.json の model より、セッション中の /model が優先される
- サブエージェントのモデルは、定義ファイルの model より、呼び出し時のモデル指定が優先される
- CLAUDE.md は指示であって強制ではない（強制は PreToolUse フック）
→ フックは使わず（非エンジニアが直せなくなるため）、/tasks で検証役のモデルを人が目で確かめる手順にした
