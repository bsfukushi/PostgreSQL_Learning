## この章で分かるようになること

- psql と pgAdmin4 の役割の違いを説明でき、場面によって使い分けられる
- コマンドプロンプトから psql を起動し、SQL とメタコマンドを実行できる
- 日本語が化けたときに、どこを揃えれば直るかが分かる
- 表の形を `\d` で確かめ、結果を `\copy` で CSV ファイルに出せる

## 1. 2つの道具の役割

PostgreSQL を操作する道具は、この資料では2つ使います。

| | psql | pgAdmin4 |
|---|---|---|
| 形 | 文字だけの画面（コマンドプロンプト） | マウスで操作する画面 |
| この資料での役割 | **主に使う道具**。SQL を実行する | **見る道具**。表の一覧や中身を眺める |
| Claude Code との関係 | Claude Code が実際に使う | Claude Code は使わない |
| 結果の形 | 文字なので、そのままコピーして質問に貼れる | 表の画面。コピーはできるが形が崩れやすい |

> 🧭 **なぜ psql を主にするのか**：Claude Code がデータベースを操作するときは、psql を実行します（第4章）。Claude Code の画面に出てくるコマンドと結果を読めるようになるには、自分でも同じ psql を使い、同じ形の結果を見慣れておくのがいちばんの近道です。

psql で覚えるのは、次の4つだけです。この資料の範囲では、これで足ります。

| 使い方 | 何をするか | Claude Code が使う場面 |
|---|---|---|
| `-c "SQL"` | SQL を1つ実行して終わる | 件数を数える、表を見るなど、ほとんどの場面 |
| `-f ファイル` | ファイルに書いた SQL を順に実行する | 初期化SQLを流す（第3章） |
| `\d` | 表の一覧や、表の列を見る | 表の形を確かめる |
| `\copy` | 結果を CSV ファイルに出す | データを取り出す |

## 2. psql を起動できるようにする

### コマンドプロンプトを開く

この資料では、コマンドを打つ画面は**コマンドプロンプト**に揃えます。スタートメニューで「cmd」と入力して開きます。

> 🧭 **なぜ PowerShell ではなくコマンドプロンプトなのか**：PowerShell でも psql は動きますが、引用符の扱いや、一部のコマンドの意味が違います。たとえば `where` は、コマンドプロンプトでは「コマンドの場所を探す」ですが、PowerShell では別の意味になります。資料のコマンドをそのまま打てるように、画面を1つに揃えます。

### psql がどこにあるかを確かめる

コマンドプロンプトで、次を実行します。

```text
where psql
```

`C:\Program Files\PostgreSQL\18\bin\psql.exe` のように場所が表示されれば、準備はできています。次の「起動する」へ進んでください。

「情報: 与えられたパターンのファイルが見つかりませんでした。」と表示されたら、psql の場所が Windows に登録されていません。次の手順で登録します。

1. スタートメニューで「環境変数」と入力し、「環境変数を編集」（自分のアカウントの環境変数）を開きます。
2. 上の欄（ユーザー環境変数）の `Path` を選び、「編集」を押します。
3. 「新規」を押し、`C:\Program Files\PostgreSQL\18\bin` と入力して、OK を2回押します。
4. **コマンドプロンプトを閉じて、開き直します。**
5. もう一度 `where psql` を実行し、場所が表示されることを確かめます。

> 🔍 **なぜ登録が要るのか**：コマンドプロンプトで `psql` と打つと、Windows は `Path` に登録されたフォルダを順に探して、`psql.exe` を見つけます。PostgreSQL のインストーラーは、このフォルダを登録しないことがあります。登録しないと、毎回 `"C:\Program Files\PostgreSQL\18\bin\psql.exe"` と長い場所を打つ必要があり、Claude Code も psql を見つけられません。

> 🔍 **なぜ開き直すのか**：コマンドプロンプトは、開いた時点の `Path` を覚えて使います。登録したあとに開いた画面でないと、新しい `Path` が反映されません。

### 起動する

```text
psql -h localhost -U postgres -d postgres
```

インストールのときに決めた `postgres` のパスワードを入力します（入力した文字は表示されません）。次のように表示されれば、接続できています。

```text
psql (18.0)
Type "help" for help.

postgres=#
```

最後の行の `postgres=#` を**プロンプト**と呼びます。ここに SQL を入力します。

| 部分 | 意味 |
|---|---|
| `postgres` | いま接続している[[データベース]]の名前 |
| `=#` | [[スーパーユーザー]]で接続している印 |
| `=>` | ふつうのロールで接続している印（第3章の `learner` で接続すると、こちらになる） |

> 🔍 **プロンプトの記号を見る習慣**：`#` が出ていたら、何でもできるロールで接続しています。打ち間違いがそのまま大きな事故になる状態なので、`#` を見たら一度手を止める、と覚えておいてください。

## 3. psql の基本

### この資料の SQL は2種類ある

この資料に出てくる SQL には、2つの役割があります。

| 種類 | 役割 | 見た目 |
|---|---|---|
| 写して実行する SQL | 道具や環境が正しく動いているかを確かめる | 上に「📋 写して実行する SQL」の帯が付く |
| 読む SQL | 中身を読んで、結果が正しいかを疑う練習の対象 | 帯が付かない（第6章から登場） |

第2〜4章の SQL は、すべて「写して実行する SQL」です。いまは中身を読めなくてかまいません。帯に書いてある章で、読み方を説明します。

> 🧭 **なぜ読み方より先に実行させるのか**：SQL を読む練習には、練習用のデータと、それを動かす道具が先に要ります（学ぶ順＝手を動かせる順）。道具を整える第2〜4章では、確かめるための SQL を「意味だけ」で使い、読み方は道具がそろった第6章から順に説明します。

### SQL は `;` で終わる

プロンプトで、次の SQL を実行します。

```sql copy=6
SELECT version();
```

:::result 1
| version |
|---|
| PostgreSQL 18.0, compiled by Visual C++ build …, 64-bit |
:::

表示される文字は PC によって違います。`PostgreSQL 18` で始まっていれば大丈夫です。

SQL の最後の `;` を忘れて Enter を押すと、プロンプトが `postgres-#` に変わり、何も実行されません。

> 🔍 **なぜ `;` が要るのか**：SQL は、長くなると何行にも分けて書きます。psql は、Enter を押しても「まだ続きがあるかもしれない」と考えて待ち、`;` が来たところで「ここまでが1つの SQL」と判断して実行します。プロンプトの `=` が `-` に変わっているのは「続きを待っている」という印です。`;` だけを打って Enter を押せば実行されます。

### メタコマンドは `\` で始まる

`\` で始まる命令は、SQL ではなく psql 自身への命令です。これを**メタコマンド**と呼びます。メタコマンドには `;` は要りません。

| メタコマンド | 何をするか |
|---|---|
| `\conninfo` | いま、どこに、どのロールで接続しているかを表示する |
| `\l` | データベースの一覧を表示する |
| `\du` | ロールの一覧を表示する |
| `\d` | 表の一覧を表示する。`\d 表の名前` で、その表の列を表示する |
| `\?` | メタコマンドの一覧（ヘルプ）を表示する |
| `\q` | psql を終わる |

日本語のキーボードでは、`\` は `¥` と表示されることがあります。同じキーなので、そのまま押してください。

### `-c`：1つ実行して終わる

psql を起動せずに、コマンドプロンプトから直接 SQL を1つだけ実行することもできます。

```text
psql -h localhost -U postgres -d postgres -c "SELECT version();"
```

実行すると結果を表示して、すぐにコマンドプロンプトに戻ります。Claude Code が psql を使うときは、ほとんどがこの形です。第4章で、Claude Code が実行してよいか尋ねてくるのも、この形のコマンドです。

## 4. 日本語が化けたら

psql の結果で日本語が `縺薙ｌ` のような意味のない文字になったら、**画面の[[文字コード]]と、psql の文字コードが揃っていない**状態です。

| どこの設定か | 確かめ方 | 変え方 |
|---|---|---|
| 画面（コマンドプロンプト） | `chcp` を実行する | `chcp 65001`（UTF-8 にする） |
| psql | psql の中で `\encoding` を実行する | `\encoding UTF8` |

この資料では、両方を UTF-8 に揃える方法を標準にします。

1. コマンドプロンプトで `chcp 65001` を実行します。
2. psql を起動し、`\encoding UTF8` を実行します。
3. 日本語を含む結果が正しく表示されることを確かめます。

手順1のあと psql を起動すると、「コンソールのコードページ (65001) が Windows のコードページ (932) と異なります」という意味の警告が出ることがあります。揃えた結果として出る警告なので、日本語が正しく表示されていれば気にしなくてかまいません。

> 🔍 **なぜ化けるのか**：データベースの中の日本語は、UTF-8 という形式の数字の並びで保存されています。psql はそれを「画面に合わせた形式」に直して送り出し、画面は「自分の形式」で読んで文字にします。この2つの形式が違うと、同じ数字の並びを別の文字として読んでしまいます。直すには、どちらか片方ではなく、両方を同じ形式に揃えます。

> 🧭 **なぜ UTF-8 に揃えるのか**：日本語の Windows の古い形式（Shift_JIS の仲間）では、一部の漢字や記号を表せません。表せない文字が出てくると、化けるのではなく psql がエラーで止まります。UTF-8 なら、データベースに入っている文字をすべて表せます。

毎回打つのが面倒な場合は、豆知識の「毎回の設定を省く」を見てください。

## 5. 表を見る：`\d`（第3章のあとで試す）

この節と次の節は、第3章で学習用のデータベース `pglearn` を作ったあとで試します。

`\d` で、表の一覧を表示します。

```text
pglearn=> \d
```

```text
               List of relations
 Schema |      Name       |   Type   |  Owner
--------+-----------------+----------+---------
 public | article_tags    | table    | learner
 public | articles        | table    | learner
 public | articles_id_seq | sequence | learner
 public | sources         | table    | learner
 public | sources_id_seq  | sequence | learner
 public | tags            | table    | learner
 public | tags_id_seq     | sequence | learner
(7 rows)
```

psql の画面の言葉は、PC の言語の設定によって日本語で表示されることもあります。この資料では英語の表示で説明します。

`sequence`（シーケンス）は、`id` の番号を順に振るための部品で、表ではありません（詳しくは第5章）。表は `table` の4つです。

`\d 表の名前` で、その表の列を表示します。

```text
pglearn=> \d articles
```

| 見る列 | 分かること |
|---|---|
| `Column` | 列の名前 |
| `Type` | 何の種類の値が入るか（`integer` は整数、`text` は文字、`timestamp with time zone` はタイムゾーン付きの日時） |
| `Nullable` | `not null` と書いてあれば、[[NULL]] は入らない |
| `Default` | 値を指定しなかったときに入る値 |

その下の `Indexes:` や `Foreign-key constraints:` などに、[[主キー]]、[[UNIQUE制約]]、[[外部キー]]などの決まりが一覧で出ます。

> 🧭 **なぜ `\d` を覚えるのか**：Claude Code が「articles には published_at 列があります」と説明しても、それが本当かは表の形を見ないと分かりません。`\d` は、説明ではなく実物を見る方法です。

## 6. 結果を CSV に出す：`\copy`（第3章のあとで試す）

SQL の結果を、Excel などで開ける CSV ファイルに出します。出力先のフォルダ `C:\pglearn\out\` を先に作っておきます。

```text copy=6
pglearn=> \copy (SELECT id, title, published_at FROM articles ORDER BY id) TO 'C:/pglearn/out/articles.csv' WITH (FORMAT csv, HEADER)
```

| 部分 | 意味 |
|---|---|
| `( ... )` の中 | 出したい結果の SELECT |
| `TO '...'` | 出力先のファイル |
| `FORMAT csv` | CSV 形式で出す |
| `HEADER` | 1行目に列の名前を入れる |

成功すると `COPY 5` と表示されます。5 は書き出した行の数です。SELECT の結果の行数と同じか、必ず確かめてください。

`\copy` を使うときは、次の3つに気をつけます。

| 気をつけること | 理由 |
|---|---|
| 全部を**1行**で書く。最後に `;` を付けない | `\copy` はメタコマンドなので、Enter を押した時点で命令が終わる。途中で改行すると、そこまでで実行されてしまう |
| ファイルの場所は `/` で区切る（`C:/pglearn/out/...`） | psql では、引用符の中の `\` が特別な意味に読まれることがある。Windows は `/` で区切っても同じ場所として扱う |
| `COPY` ではなく `\copy` を使う | 下の 🔍 を参照 |

> 🔍 **`\copy` と `COPY` の違い**：`COPY`（`\` なし）は SQL で、ファイルを書くのは **PostgreSQL のサーバー**です。サーバーは、あなたとは別の Windows のアカウントで動いていることが多く、あなたのフォルダに書き込めなかったり、書き込むのに特別な権限（スーパーユーザーなど）が要ったりします。`\copy` は psql の命令で、ファイルを書くのは **psql（つまり、あなた）**です。自分の PC の自分のフォルダに出すときは、`\copy` を使います。

### Excel で開くと日本語が化ける

`articles.csv` をダブルクリックして Excel で開くと、日本語が化けることがあります。ファイルが壊れているわけではありません。

> 🔍 **なぜ Excel だと化けるのか**：`\copy` は、ファイルを UTF-8 で書きます。Excel は、CSV をダブルクリックで開くと、ファイルの形式を Shift_JIS の仲間だと考えて読むことがあります。第4節と同じで、書いた側と読む側の形式が揃っていないために化けます。

Excel で開くときは、Excel を先に起動し、「データ」タブの「テキストまたは CSV から」でファイルを選び、「元のファイル」を「65001: Unicode (UTF-8)」にして読み込みます。

## 7. pgAdmin4 で見る

pgAdmin4 は、データベースの中を、フォルダをたどるように眺められる道具です。

1. pgAdmin4 を起動し、左の一覧で「Servers」を開きます。PostgreSQL 18 のサーバーが登録されていれば、それを選び、`postgres` のパスワードを入力します。
2. 「Databases」→ データベースの名前 →「Schemas」→「public」→「Tables」の順に開くと、表の一覧が出ます（第3章のあとなら、`pglearn` の下に4つの表があります）。
3. 表を右クリックし、「View/Edit Data」→「All Rows」で中身を表示できます。

pgAdmin4 の表の画面では、[[NULL]] は `[null]` と表示されます。空の文字とは区別されます。

この資料では、pgAdmin4 は**見るだけ**に使います。次の2つはしないでください。

| しないこと | 理由 |
|---|---|
| 表の画面で、値を直接書き換える | どの行の何を変えたかが SQL として残らないので、あとから確かめられない。元に戻すときも、何を戻せばよいか分からない |
| pgAdmin4 を開いたまま、完全リセット（第3章）をする | pgAdmin4 がデータベースに接続したままになり、`DROP DATABASE` が「使用中」で止まる |

> 🧭 **なぜ「見るだけ」なのか**：この資料で身につけたいのは、Claude Code が出した SQL と結果を読む力です。マウスの操作で変更すると、その変更は SQL の形で目に入りません。変更は SQL で行い、psql で結果を確かめる、という形に揃えておくと、Claude Code に任せたときも同じ見方で確かめられます。

## 8. 手を動かす

### 今すぐ試す

1. コマンドプロンプトで `where psql` を実行し、psql の場所が表示されることを確かめます。表示されなければ、第2節の手順で登録します。
2. `chcp 65001` を実行してから、`postgres` で psql を起動します。プロンプトの最後が `#` であることを確かめます。
3. `\encoding UTF8` を実行します。
4. `SELECT version();` を実行し、`PostgreSQL 18` で始まることを確かめます。
5. 次に `;` を付けずに `SELECT 1` と打って Enter を押し、プロンプトが `postgres-#` に変わることを確かめます。`;` だけを打って Enter を押すと実行されます。
6. `\conninfo`、`\l`、`\du` を順に実行し、何が表示されるかを見ます。`\du` には、いまは `postgres` しかいないはずです。
7. `\q` で終わり、`-c` の形で `SELECT version();` を実行します。
8. pgAdmin4 を起動し、サーバーに接続して、「Databases」の下にあるデータベースを見ます。

### 第3章のあとで試す

1. `learner` で `pglearn` に接続し、プロンプトの最後が `>` であることを確かめます（`pglearn=>`）。
2. `\d` で表が4つあること、`\d articles` で `source_id` 列に `not null` が付いていないことを確かめます（配信元が不明な記事があるため）。

続けて、次の SQL で記事の最初の3本を表示します。

```sql copy=6
SELECT id, title FROM articles ORDER BY id LIMIT 3;
```

:::result 3
| id | title |
|---:|---|
| 1 | クラウド利用料、来春から改定へ |
| 2 | 社内AIの導入率が過半数に |
| 3 | 半導体工場の新設計画を発表 |
:::

最後に、出力と pgAdmin4 を試します。

1. 第6節の `\copy` で `articles.csv` を出し、`COPY 5` と表示されることを確かめます。
2. Excel の「テキストまたは CSV から」で開き、日本語が正しく表示されることを確かめます。
3. pgAdmin4 で `pglearn` の4つの表を見つけ、`articles` の中身を表示して、`source_id` が `[null]` の行を見つけます。確認したら、pgAdmin4 を閉じます。

## 💡 Claude Codeで使うなら

:::claude 頼み方の例
Claude Code を使い始めるのは第4章からです。第4章を終えたあとで、表の形を確かめるときと、CSV に出すときの例を載せておきます。第4章の作業フォルダ（`C:\pglearn\`）で頼むときの形です。接続先・してはいけないこと・検証材料 a・b・d・e・検証役（`sql-checker`）は `CLAUDE.md` に書いてあるので、依頼に書くのは①目的と③使う表、それにこの章で足すことだけです。

```text
PostgreSQL 18 の学習用DBで、articles 表の列を確かめてください。
① 目的: articles にどんな列があり、どの列に NULL が入りうるかを知りたい
③ 使う表: articles
- psql の \d articles の結果を、加工せずにそのまま見せる
```

```text
PostgreSQL 18 の学習用DBから、記事の id・タイトル・公開日時を CSV に出してください。
① 目的: 記事の一覧を Excel で見たい。全件を id の順に出す
③ 使う表: articles
- psql の \copy を使い、C:/pglearn/out/articles.csv に出す。1行目は列名
- 実行前に、\copy の行をそのまま見せる
- b として、COPY のあとに表示された行数と、articles の件数を並べる
```

**出てきたものの検証ポイント**

1. 表の形の説明が、`\d` の結果（実物）と一致しているか
2. `\copy` を使っているか。`COPY`（`\` なし）でサーバーにファイルを書かせていないか
3. `COPY 5` の行数が、出したかった件数と一致しているか

**起きがちな失敗と、その理由**

- **`psql` が見つからないと言われる**：psql の場所が `Path` に登録されていないか、登録したあとに Claude Code を起動し直していないことが原因です。Claude Code も、起動した時点の `Path` を使います。
- **`\d` の結果ではなく、要約した説明だけが返ってくる**：Claude Code は、読みやすく言い換えて報告することがあります。言い換えの途中で列が抜けたり、型が違って書かれたりしても気づけないので、「加工せずにそのまま見せる」と頼みます。
- **CSV の件数が足りない**：`\copy` の中の SELECT に、頼んでいない条件（`WHERE` や `LIMIT`）が入っていることがあります。`COPY` の行数と、元の表の件数を必ず比べます。
:::

## 確認問題

:::quiz Q1. psql で SELECT を打って Enter を押したのに、結果が出ず、プロンプトが `pglearn-#` になりました。何が起きていますか？
SQL の最後に `;` が無いため、psql が「続きがある」と考えて待っています。プロンプトの `=` が `-` に変わっているのが、その印です。`;` だけを打って Enter を押せば実行されます。（`#` なので、スーパーユーザーで接続していることにも気づけるとなお良いです。）
:::

:::quiz Q2. Claude Code が「CSV に出力しました」と報告し、実行したのは `psql ... -c "COPY (SELECT ...) TO 'C:/pglearn/out/articles.csv' ..."` でした。ところが、そのフォルダにファイルがありません（またはエラーになっています）。どこを疑いますか？
`\copy` ではなく `COPY` を使っていることを疑います。`COPY` は PostgreSQL のサーバーがファイルを書くので、あなたのフォルダには書けなかったり、権限が無いというエラーになったりします。`\copy` を使うように頼み直します。
:::

:::quiz Q3. 同僚から「psql の結果の日本語が化ける」と相談されました。`chcp` は 65001、psql の `\encoding` は SJIS でした。どうすれば直りますか？
画面（UTF-8）と psql（SJIS）の文字コードが揃っていません。psql の中で `\encoding UTF8` を実行し、両方を UTF-8 に揃えます。片方だけを変えても直らない、というのがポイントです。
:::

:::why 📚 なぜ？豆知識（読み飛ばしてもかまいません）

### 🔍 毎回の設定を省く

`chcp 65001` と `\encoding UTF8` を毎回打つ代わりに、次の方法があります。

- **psql の文字コード**：ユーザー環境変数に `PGCLIENTENCODING` という名前で `UTF8` を登録すると、psql は起動したときから UTF-8 でやり取りします（登録のしかたは第2節の `Path` と同じ画面です）。
- **画面の文字コード**：Windows Terminal など、最初から UTF-8 で表示する画面を使う方法もあります。

どちらも PC 全体の設定を変えるので、変えたことをメモしておき、困ったときに資料作成者へ伝えてください。

### 🔍 結果が長いとき

psql は、結果が画面に入りきらないとき、1画面ずつ止めて表示することがあります。スペースキーで次の画面へ進み、`q` で表示を終わります。Claude Code が `-c` で実行したときは、画面ではないので止まりません。

### 🧭 pgAdmin4 の Query Tool について

pgAdmin4 にも、SQL を実行する画面（Query Tool）があります。psql と同じ SQL を実行できますが、既定では1つの SQL を実行するたびに、変更がすぐ確定します。「やってから戻す」方法（`BEGIN` と `ROLLBACK`）は第8章で扱うので、それまでは、変更する SQL を Query Tool で実行しないでください。

さらに知りたい人は、公式ドキュメント（PostgreSQL 18）の [psql](https://www.postgresql.org/docs/18/app-psql.html) と [文字セットのサポート](https://www.postgresql.org/docs/18/multibyte.html) を参照してください。
:::

:::
