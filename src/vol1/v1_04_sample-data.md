## この章で分かるようになること

- この資料で使う学習用の[[データベース]]と[[ロール]]を作り、サンプルデータを入れられる
- 何をしても、数分で「最初の状態」に戻せる。戻す方法が2段階あることと、その使い分けが分かる
- 自分の PC の設定（版・[[文字コード]]・[[照合順序]]・タイムゾーン）を確かめ、ほかのメンバーと揃っているかを確認できる

## 1. この章で作るもの

この資料では、学習専用のデータベースを1つ作り、その中だけで練習します。名前は次のとおり固定します。以降の章も、Claude Code への頼み方の例も、すべてこの名前を使います。

| 種類 | 名前 | 役割 |
|---|---|---|
| データベース | `pglearn` | 学習用。壊してよい |
| ロール（接続するユーザー） | `learner` | 学習用。`pglearn` の持ち主。表を作る・書き換える・消すことができる |
| ロール（接続するユーザー） | `reviewer` | 検証用。`pglearn` の表を**読むことしかできない** |
| 初期化SQL | `99_reset.sql` → `01_schema.sql` → `02_seed.sql` | この順に流すと最初の状態になる |

PostgreSQL をインストールしたときに作られた `postgres` というロールは、何でもできる特別なロール（[[スーパーユーザー]]）です。`postgres` を使うのは、この章の最初の「作る」作業だけにします。練習は `learner` で行います。`reviewer` は、第5章で「Claude Code が書いた SQL を、別のモデルに検証させる」ときに使います。

> 🧭 **なぜ専用のロールを作るのか**：`postgres` で練習すると、打ち間違い1つで学習用以外のデータベースまで消せてしまいます。`learner` は `pglearn` の持ち主なので、その中では表を作ることも消すこともできますが、ほかのデータベースの表は消せません。壊れてもよい範囲に、操作できる範囲を合わせておくのが目的です。理由は第5章でも詳しく扱います。

### 初期化SQLの3つのファイル

付録Dに、3つのファイルの中身がそのまま載っています。それぞれ、次のことをします。

| ファイル | やること | 流す順番 |
|---|---|---|
| `99_reset.sql` | 学習用の4つの表を消す | 1番目 |
| `01_schema.sql` | 4つの表を作り（中身は空）、`reviewer` に読む権限を与える | 2番目 |
| `02_seed.sql` | サンプルデータを入れる | 3番目 |

ファイル名の数字は「中身が何をするか」の目印で、`99` は「最後の手段（消す）」の意味です。流す順番とは一致していないので、順番は上の表で覚えてください。

> 🧭 **なぜ「正」をSQLファイルにするのか**：データベースの中身は、練習するたびに変わります。最初の状態を「ファイル」として持っておけば、何度でも同じ状態に戻せますし、メンバー全員が同じデータで練習できます。データベースの中身ではなく、ファイルのほうを「正」と考えます。

## 2. 学習用のデータベースとロールを作る（最初の1回だけ）

第3章の方法で、`postgres` ロールで psql を起動します。

```text
psql -h localhost -U postgres -d postgres
```

インストールのときに決めた `postgres` のパスワードを入力すると、`postgres=#` と表示されます。行の先頭の `postgres` は、いま接続しているデータベースの名前です。ここで次の5行を、1行ずつ実行します。

```text
CREATE ROLE learner LOGIN;
\password learner
CREATE ROLE reviewer LOGIN;
\password reviewer
CREATE DATABASE pglearn OWNER learner;
```

| 行 | やっていること |
|---|---|
| 1行目 | ログインできるロール `learner` を作る |
| 2行目 | `learner` のパスワードを決める。2回入力を求められる。画面には表示されない |
| 3行目 | ログインできるロール `reviewer` を作る |
| 4行目 | `reviewer` のパスワードを決める |
| 5行目 | データベース `pglearn` を作り、持ち主を `learner` にする |

3つのロール（`postgres`・`learner`・`reviewer`）のパスワードは、すべて別のものにしてください。第5章で、`learner` と `reviewer` のパスワードを PC の中のファイルに保存します。

> 🔍 **なぜ `CREATE ROLE ... PASSWORD '...'` と書かないのか**：SQL の中にパスワードを書くと、psql の入力履歴などに、そのままの文字で残ることがあります。`\password` は、入力したパスワードを psql の中で暗号化してからサーバーへ送るので、平文が残りません。

> 🔍 **なぜ持ち主を `learner` にするのか**：PostgreSQL 15 以降は、データベースの持ち主でないロールは、そのデータベースの中に表を作れません。持ち主を `learner` にしておくと、`learner` だけで初期化SQLを流せます。

> 🧭 **なぜ読むだけのロールを作るのか**：第5章では、Claude Code が書いた SQL を、別のモデルに検証させます。検証役も SQL を実行しますが、検証役がうっかりデータを書き換えてしまうと、検証そのものが信用できなくなります。`reviewer` は、表を読む権限しか持たないので、書き換える SQL を実行しても PostgreSQL がエラーで止めます。「気をつける」ではなく、「できない」状態にしておきます。

> 🔍 **読む権限は、いつ与えるのか**：この時点では、まだ表がありません。読む権限は表ごとに与えるもので、表を消して作り直すと、権限も一緒に消えます。そこで、表を作る `01_schema.sql` の最後で、毎回 `reviewer` に読む権限を与えるようにしてあります。リセットのたびに、権限も元どおりになります。

終わったら `\q` で psql を終了します。この先、`postgres` で接続するのは、第4節の「完全リセット」をするときだけです。

## 3. サンプルデータを入れる

### ファイルを置く

付録Dの3つのファイルを、次のフォルダに保存します。

```text
C:\pglearn\sql\99_reset.sql
C:\pglearn\sql\01_schema.sql
C:\pglearn\sql\02_seed.sql
```

> 🧭 **なぜこの場所なのか**：フォルダの名前に空白や日本語が入っていると、コマンドで場所を指定するときに引用符が必要になり、間違えやすくなります。全員が同じ場所に置くと、質問するときも「どのファイルか」で迷いません。

ファイルは、文字コードを **UTF-8** にして保存します（メモ帳なら「名前を付けて保存」の画面の下にある「エンコード」で選びます）。どのファイルも、1行目は `SET client_encoding = 'UTF8';` です。

> 🔍 **なぜ1行目で文字コードを指定するのか**：psql は、PC の言語の設定から「やり取りする文字の形式」を決めることがあります。日本語の Windows では、それが UTF-8 ではない形式（Shift_JIS の仲間）になる場合があります。そのまま UTF-8 のファイルを流すと、日本語のデータが化けたり、エラーになったりします。ファイルの1行目で「このファイルは UTF-8 で読んで」と指定しておけば、PC の設定に左右されません。

### 3つのファイルを順に流す

コマンドプロンプトで、次の3行を順に実行します。どの行も、`learner` で `pglearn` に接続し、ファイルを1つ流します。

```text
psql -h localhost -U learner -d pglearn -v ON_ERROR_STOP=1 -f C:\pglearn\sql\99_reset.sql
psql -h localhost -U learner -d pglearn -v ON_ERROR_STOP=1 -f C:\pglearn\sql\01_schema.sql
psql -h localhost -U learner -d pglearn -v ON_ERROR_STOP=1 -f C:\pglearn\sql\02_seed.sql
```

毎回、`learner` のパスワードを聞かれます（第5章で聞かれないようにします）。

コマンドの各部分は、次の意味です。

| 部分 | 意味 |
|---|---|
| `-h localhost` | 自分の PC の PostgreSQL に接続する |
| `-U learner` | ロール `learner` で接続する |
| `-d pglearn` | データベース `pglearn` に接続する |
| `-v ON_ERROR_STOP=1` | エラーが1つでも出たら、そこで止まる |
| `-f ファイル` | ファイルに書かれた SQL を上から順に実行する |

> 🔍 **なぜ `ON_ERROR_STOP=1` が必要なのか**：psql は、何も指定しないと、エラーが出てもファイルの次の文へ進みます。最後まで流れてしまうと、途中のエラーが画面の上へ流れて見えなくなり、「最後の行は普通に見えるのに、データが足りない」という状態になります。最初のエラーで止めておけば、どこで失敗したかが画面の最後に残ります。

初回は、`99_reset.sql` を流したときに「表が存在しないので飛ばした」という意味の `NOTICE` が4行出ます。消す表がまだ無いだけなので、問題ありません（`NOTICE` はお知らせで、エラーではありません）。

### 入ったことを確かめる

`learner` で `pglearn` に接続し、4つの表の件数を数えます。

```text
psql -h localhost -U learner -d pglearn
```

```sql
SELECT
    (SELECT COUNT(*) FROM sources)      AS sources,
    (SELECT COUNT(*) FROM articles)     AS articles,
    (SELECT COUNT(*) FROM tags)         AS tags,
    (SELECT COUNT(*) FROM article_tags) AS article_tags;
```

:::result 1
| sources | articles | tags | article_tags |
|---:|---:|---:|---:|
| 3 | 5 | 4 | 8 |
:::

**3・5・4・8** がこの資料の「最初の状態」です。以降の章の結果表は、すべてこの状態から実行したものです。数字が違うときは、次の節の方法で戻してから進んでください。

## 4. 元に戻す：2つの段階

練習していると、データを書き換えたり、Claude Code が新しい表を作ったりします。元に戻す方法は2段階あります。

| | 軽いリセット | 完全リセット |
|---|---|---|
| やること | 3つのファイルを、もう一度同じ順に流す | データベースごと消して作り直し、3つのファイルを流す |
| 接続するロール | `learner` | 作り直すところだけ `postgres` |
| 戻るもの | 学習用の4つの表 | データベースの中のすべて |
| 戻らないもの | 4つの表**以外**に作られた表など | なし |
| 使う場面 | ふだん。章の練習の前 | 見覚えのない表がある、何が変わったか分からない |

### 軽いリセット

第3節の3行を、もう一度そのまま実行します。`99_reset.sql` が4つの表を消し、`01_schema.sql` と `02_seed.sql` が作り直します。

> 🔍 **なぜ「消す → 作る → 入れる」の順なのか**：表を作り直すと、[[主キー]]の番号（`id`）も 1 から振り直されます。本文の SQL は「配信元の id が 1 ならテック日報」という前提で書いているので、データだけ消して入れ直すより、表ごと作り直すほうが確実に同じ状態になります。

> 🔍 **なぜ消す順番が決まっているのか**：`articles` は `sources` を参照しています（[[外部キー]]）。参照されている側を先に消そうとすると、「まだ参照している表がある」というエラーになります。だから `99_reset.sql` は、参照している側（`article_tags`）から順に消しています。

### 完全リセット

`99_reset.sql` が消すのは、名前を知っている4つの表だけです。練習中に Claude Code が作った表（例：`articles_backup`）は残ります。何が増えたか分からなくなったら、データベースごと作り直します。

1. pgAdmin4 を開いていたら閉じます。ほかの psql も終了します。
2. `postgres` で接続し、データベースを消して作り直します。

    ```text
    psql -h localhost -U postgres -d postgres
    ```

    ```text
    DROP DATABASE pglearn;
    CREATE DATABASE pglearn OWNER learner;
    \q
    ```

3. 第3節の3行（3つのファイル）を流し、件数が 3・5・4・8 になることを確かめます。

ロール（`learner` と `reviewer`）は、データベースの外にあるので、`DROP DATABASE` では消えません。作り直す必要はありません。

> 🔍 **なぜ pgAdmin4 を閉じるのか**：だれか（pgAdmin4 や、別の画面の psql）が `pglearn` に接続していると、`DROP DATABASE` は「ほかのユーザーが使用中」というエラーで止まります。消してよいかどうかを PostgreSQL は判断できないので、使用中のデータベースは消さないようにできています。

`DROP DATABASE` は、指定したデータベースの中身をすべて消し、元に戻す方法はありません。必ず `pglearn` と書いてあることを確かめてから実行してください。

## 5. 全員の設定を揃える

同じ SQL を実行しても、PC の設定が違うと、並び順や日時の表示が変わることがあります。`learner` で `pglearn` に接続し、次の SQL を実行します。

```sql
SELECT
    current_setting('server_version')  AS version,
    current_setting('server_encoding') AS encoding,
    d.datlocprovider                   AS locale_provider,
    d.datcollate                       AS lc_collate,
    current_setting('TimeZone')        AS timezone
FROM pg_database AS d
WHERE d.datname = current_database();
```

:::result 1
| version | encoding | locale_provider | lc_collate | timezone |
|---|---|---|---|---|
| 18.0 | UTF8 | c | Japanese_Japan.932 | Asia/Tokyo |
:::

上の表は表示の一例です。それぞれの列の意味と、確かめることは次のとおりです。

| 列 | 意味 | 確かめること |
|---|---|---|
| `version` | PostgreSQL の版 | `18.` で始まるか |
| `encoding` | データベースの[[文字コード]] | `UTF8` か |
| `locale_provider` | 並び順のルールをどこから持ってくるか | 全員が同じか |
| `lc_collate` | 文字の並び順のルール（[[照合順序]]） | 全員が同じか |
| `timezone` | 日時を表示するときのタイムゾーン | `Asia/Tokyo` か |

結果の1行を、資料作成者に送ってください。全員の結果を並べて、違いがないかを確かめます。

> 🔍 **なぜ並び順の設定を揃えるのか**：`ORDER BY title` の並び順は、`lc_collate` の設定で決まります。英字の大文字と小文字、全角と半角、ひらがなとカタカナのどれを先に並べるかが、設定によって変わります。設定が違うと、同じ SQL でも結果の順番が人によって違い、「Claude Code の結果が資料と違う」と迷う原因になります。

> 🔍 **なぜタイムゾーンを確かめるのか**：記事の公開日時は、時刻とタイムゾーンを一緒に保存しています（第2章）。表示するときは、`timezone` の設定の時刻に直して見せます。設定が `UTC` になっていると、同じ記事の公開日時が9時間ずれて見えます。

## 6. 手を動かす

1. 第2節の手順で、ロール `learner` とデータベース `pglearn` を作ります（最初の1回だけ）。
2. 第3節の3行を流し、件数が 3・5・4・8 になることを確かめます。
3. 次の SQL で、記事を1本消してみます。

    ```text
    DELETE FROM articles WHERE id = 5;
    ```

    件数を数え直し、`articles` が 4 になったことを確かめます。

4. 軽いリセットをして、件数が 3・5・4・8 に戻ることを確かめます。
5. `reviewer` で接続し、読めるが書き換えられないことを確かめます。

    ```text
    psql -h localhost -U reviewer -d pglearn
    ```

    ```text
    SELECT COUNT(*) FROM articles;
    DELETE FROM articles WHERE id = 5;
    ```

    1行目は `5` が表示され、2行目は `permission denied for table articles`（表 articles への権限がない）というエラーになります。エラーになれば成功です。
6. 第5節の SQL を実行し、結果を資料作成者に送ります。

手順4で「戻せる」ことを一度体験しておくと、以降の章で安心して試せます。

## 💡 Claude Codeで使うなら

:::claude 頼み方の例
Claude Code を使い始めるのは第5章からです。第5章を終えたあとで、リセットを頼むときの例を載せておきます。

```text
PostgreSQL 18 の学習用DB（pglearn）を、軽いリセットで最初の状態に戻してください。
- 接続: ホスト localhost、ロール learner、データベース pglearn
- C:\pglearn\sql\ の 99_reset.sql → 01_schema.sql → 02_seed.sql の順に流す
- psql には -v ON_ERROR_STOP=1 を付ける
- 実行前に、実行するコマンドを3行とも見せる
- 実行後、sources / articles / tags / article_tags の件数を表示する（3・5・4・8 になるはず）
- pglearn 以外のデータベースには接続しない
```

**出てきたものの検証ポイント**

1. 実行するコマンドの `-d` が `pglearn`、`-U` が `learner` になっているか
2. 3つのファイルの順番が「99 → 01 → 02」になっているか
3. `-v ON_ERROR_STOP=1` が付いているか
4. 最後の件数が 3・5・4・8 か。報告の文章ではなく、表示された数字で確かめる

**起きがちな失敗と、その理由**

- **エラーが出ていたのに「完了しました」と報告される**：`ON_ERROR_STOP` を付けずに流すと、psql は途中のエラーを飛ばして最後まで進みます。最後の表示だけを見ると成功したように見えるためです。件数を数えさせれば、足りないことに気づけます。
- **「リセットしたのに、作った覚えのない表が残っている」**：軽いリセットは4つの表しか消しません。Claude Code が途中で作った表を消したいときは、完全リセットを自分で行います。
- **`postgres` で接続したコマンドが出てくる**：初期化SQLは `learner` だけで流せます。`postgres` で流させないでください。理由は第5章で説明します。
:::

## 確認問題

:::quiz Q1. Claude Code に軽いリセットを頼んだら「3つのファイルを流し、リセットが完了しました」と報告されました。件数を数えさせると、sources 3、articles 0、tags 0、article_tags 0 でした。どこを疑いますか？
`02_seed.sql` の途中でエラーが出て、残りが入っていないことを疑います。実行したコマンドに `-v ON_ERROR_STOP=1` が付いていたか、出力の途中にエラーが出ていないかを確かめます。原因が分からなくても、まずは自分で軽いリセットをやり直し、件数が 3・5・4・8 になれば先へ進めます。
:::

:::quiz Q2. 軽いリセットをして件数は 3・5・4・8 に戻りました。ところが pgAdmin4 で見ると、`articles_backup` という表がまだあります。なぜですか？
`99_reset.sql` が消すのは、学習用の4つの表だけだからです。`articles_backup` は練習中に作られた表なので、軽いリセットでは消えません。何が増えたか分からないときは、完全リセットでデータベースごと作り直します。
:::

:::quiz Q3. 同じ SQL（記事をタイトル順に並べる）を実行したのに、あなたと同僚とで、結果の並び順が違いました。データはどちらも 3・5・4・8 です。どこを疑いますか？
第5節の設定のうち、`locale_provider` と `lc_collate`（並び順のルール）が2人で違っていないかを疑います。データが同じでも、並び順のルールが違えば順番が変わります。
:::

:::why 📚 なぜ？豆知識（読み飛ばしてもかまいません）

### 🔍 `-1` を付けると「全部成功か、何もしないか」になる

psql に `-1`（`--single-transaction`）を付けると、ファイル全体を1つのまとまり（[[トランザクション]]）として実行します。`-v ON_ERROR_STOP=1` と一緒に使うと、途中で失敗したときに、それまでの変更も取り消されます。

```text
psql -h localhost -U learner -d pglearn -v ON_ERROR_STOP=1 -1 -f C:\pglearn\sql\02_seed.sql
```

この資料の初期化SQLは、失敗したら最初から流し直せばよいので、`-1` を付けなくても困りません。また、`CREATE DATABASE` や `DROP DATABASE` のように、トランザクションの中では実行できない文を含むファイルには使えません。トランザクションは第8章で扱います。

### 🧭 「最初の状態」をバックアップではなくSQLで持つ理由

データベースの中身をそのまま保存する方法（`pg_dump`）もあります。ただ、保存した中身は、人が読んでも「何が入っているか」が分かりにくく、少し直したいときにも扱いにくい形です。初期化SQLなら、ファイルを読めば中身が分かり、直したところも記録に残ります。この資料では、SQLファイルを「正」、`pg_dump` を「ある時点の写真」として使い分けます（第16章）。

### 🔍 `DROP DATABASE ... WITH (FORCE)`

`DROP DATABASE pglearn WITH (FORCE);` と書くと、接続している人を強制的に切ってから消します（切れない接続が残っていると、それでも失敗します）。便利ですが、「だれが何をしているか分からないまま消す」操作です。この資料では、自分で接続を閉じてから、`WITH (FORCE)` を付けずに消す方法を標準にしています。

さらに知りたい人は、公式ドキュメント（PostgreSQL 18）の [psql](https://www.postgresql.org/docs/18/app-psql.html) と [DROP DATABASE](https://www.postgresql.org/docs/18/sql-dropdatabase.html) を参照してください。
